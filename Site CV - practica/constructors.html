CV Probleme Constructori C# Sarcina Suplimentara Declaratie

Tema: Constructori și Destructori

O analiză clară despre crearea, configurarea și ciclul de viață al obiectelor în C#

Când lucrăm cu variabile simple (cum ar fi un int), inițializarea este directă: scriem int x = 10; și gata. Dar în cazul obiectelor din lumea reală, lucrurile sunt mai complexe. Un obiect nu poate apărea în memorie „gol” sau cu date invalide. Pentru a asigura o pornire corectă și sigură a fiecărui obiect, limbajul C# folosește două mecanisme esențiale: Constructorii și Destructorii.

Regulile de aur ale unui constructor:
  • Are întotdeauna exact același nume cu clasa în care este definit.
  • Nu returnează niciun tip de date (nici măcar void).
  • Se execută automat, o singură dată, în momentul în care creăm obiectul folosind operatorul new.

1. Constructorii Impliciti (Fără Parametri)

Constructorul implicit se ocupă de aducerea obiectului într-o stare neutră. Dacă uităm sau alegem să nu scriem niciun constructor în clasa noastră, C# ne oferă unul automat din oficiu (generat de compilator), care pune toate numerele pe 0 și textele pe null. Totuși, îl putem scrie chiar noi ca să definim valorile noastre de pornire.

Vezi codul: Constructor Implicit 
public class Time 
{
    private int hour;
    private int minute;
    private int second;

    // Constructor implicit (definit de programator)
    public Time() 
    {
        hour = 0;
        minute = 0;
        second = 0;
        Console.WriteLine("Apel constructor implicit: Timpul a fost resetat.");
    }
}

2. Constructorii cu Parametri

De cele mai multe ori, nu vrei ca obiectele tale să fie identice la pornire. Constructorul cu parametri ne permite să trimitem valori din exterior chiar în momentul creării, oferind obiectului atribute unice din prima secundă. Parametrii pot avea și valori implicite (valori de rezervă în caz că utilizatorul nu trimite toate datele).

Vezi codul: Constructor cu Parametri 
public class Time 
{
    private int hour;
    private int minute;
    private int second;

    // Constructor cu valori implicite (daca nu trimitem toti parametrii, se folosesc cei de rezerva)
    public Time(int h = 0, int m = 0, int s = 0) 
    {
        hour = h;
        minute = m;
        second = s;
    }
}

// Utilizare flexibilă:
// Time t1 = new Time(10, 30, 0); // Seteaza ora 10:30:00
// Time t2 = new Time(12);       // Seteaza ora 12:00:00 (minutele si secundele raman 0)

3. Constructorul de Copiere

Atenție la o confuzie des întâlnită! Dacă scriem obiect1 = obiect2;, noi nu copiem obiectul, ci doar copiem o referință (ambele variabile vor arăta către aceeași zonă din memorie). Dacă modifici ceva în obiect1, se va schimba automat și în obiect2.

Pentru a face o copiere reală și independentă (o clonă fizică), folosim un constructor de copiere. Acesta primește ca parametru un obiect existent de același tip și îi copiază manual valorile câmp cu câmp într-un obiect complet nou.

Vezi codul: Constructor de Copiere & Clasa Date 
using System;

public class Date 
{
    private int day, month, year;

    // Constructor cu parametri
    public Date(int d, int m, int y) 
    {
        day = d;
        month = m;
        year = y;
    }

    // Constructor de copiere (creeaza o instanta complet noua pe baza alteia)
    public Date(Date other) 
    {
        this.day = other.day;
        this.month = other.month;
        this.year = other.year;
    }

    public void Print() 
    {
        Console.WriteLine($"{day}/{month}/{year}");
    }
}

// Demonstratie in Main:
// Date date1 = new Date(15, 9, 2018);
// Date date2 = new Date(date1); // Clona independenta

4. Cuvântul cheie „this”

Cuvântul cheie this reprezintă o referință directă către obiectul curent în care ne aflăm. Îl folosim în două situații principale foarte practice:

  • Evitarea conflictelor de nume: Atunci când parametrii constructorului au exact aceleași nume ca și câmpurile clasei (ex: this.x = x;).
  • Chaining (Apel în lanț): Când vrem ca o metodă să returneze obiectul curent (return this;), permițându-ne să apelăm mai multe metode una după alta pe aceeași linie de cod.
Vezi codul: Utilizarea "this" si Apelul in Lant 
using System;

public class Num 
{
    private int x;

    // 1. Rezolvarea conflictului de nume
    public Num(int x) 
    {
        this.x = x; // "this.x" este campul clasei, "x" este parametrul primit
    }

    // 2. Returnarea instantei pentru apel in lant
    public Num Incrementeaza() 
    {
        this.x++;
        return this; // Returneaza obiectul curent
    }

    public void Print() 
    {
        Console.WriteLine($"Valoare: {x}");
    }
}

// Utilizare (Method Chaining):
// Num n = new Num(3);
// n.Incrementeaza().Incrementeaza(); // Valoarea devine 5 direct pe o singura linie!

5. Destructorii în C#

Dacă constructorul este cel care dă viață unui obiect, destructorul se ocupă de curățarea resurselor înainte ca acel obiect să fie șters definitiv din memorie de către Garbage Collector.

În C#, gestionarea memoriei este automată, deci nu avem nevoie mereu de destructori. Îi scriem doar în cazuri speciale (de exemplu, când deschidem un fișier text sau o conexiune la o bază de date și trebuie neapărat să le închidem înainte ca obiectul să dispară).

Caracteristicile unui destructor:
  • Numele său este format din caracterul tilda (~) urmat de numele clasei (ex: ~Time()).
  • Nu are modificatori de acces (niciodată nu scriem public sau private în fața lui).
  • Nu are parametri și nu returnează nicio valoare.
  • O clasă poate avea un singur destructor.
Vezi codul: Destructor & Clasa CreateAndDestroy 
using System;

public class CreateAndDestroy 
{
    private int id;

    // Constructor
    public CreateAndDestroy(int value) 
    {
        id = value;
        Console.WriteLine($"Constructor apelat pentru obiectul {id}");
    }

    // Destructor - se apeleaza automat cand Garbage Collector sterge obiectul
    ~CreateAndDestroy() 
    {
        Console.WriteLine($"Destructor apelat pentru obiectul {id} (Resurse eliberate).");
    }
}

6. Studiu de Caz: Implementarea Tipului Abstract Array

Pentru a pune toate cunoștințele la un loc, iată o implementare completă a unei clase numite Array. Aceasta gestionează un vector alocat dinamic și demonstrează perfect cum lucrează în echipă un constructor implicit, unul cu dimensiune stabilită și un constructor de copiere profundă (deep copy):

Vezi Studiul de Caz: Clasa Array 
using System;

public class Array 
{
    private int[] t; // Vectorul intern
    private int c;   // Capacitatea vectorului

    // 1. Constructor implicit
    public Array() 
    {
        c = 0;
        t = null;
    }

    // 2. Constructor cu dimensiune primita ca parametru
    public Array(int k) 
    {
        c = k;
        t = new int[c];
        PutN(100); // Initializam automat cu valori intre 0 si 99
    }

    // 3. Constructor de copiere profund (Deep Copy)
    public Array(Array other) 
    {
        if (other.c == 0) 
        {
            c = 0;
            t = null;
        }
        else 
        {
            c = other.c;
            t = new int[c]; // Alocam o zona noua de memorie
            for (int i = 0; i < c; i++) 
            {
                t[i] = other.t[i]; // Copiem valorile una cate una
            }
        }
    }

    // Umple vectorul cu valori aleatorii (Random)
    public void PutN(int n) 
    {
        if (c == 0) 
        {
            c = 10;
            t = new int[c];
        }
        Random rnd = new Random();
        for (int i = 0; i < c; i++) 
        {
            t[i] = rnd.Next(n);
        }
    }

    // Afisarea elementelor vectorului
    public void Print() 
    {
        if (c == 0) 
        {
            Console.WriteLine("Vectorul este gol.");
        }
        else 
        {
            Console.WriteLine("Elemente: " + string.Join(" ", t));
        }
    }
}
